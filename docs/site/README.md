# CLI documentation site

Public URL: https://docs.botpager.reostack.com/.

Nextra 4 docs for the public BotPager CLI, organized with Diátaxis. Source is in `content/`; the existing CLI release-verification document is outside this app and stays intact.

## Local development and preview

Use Node.js 24 and npm from this directory:

```sh
npm ci
npm run dev
```

For a production static preview:

```sh
npm run build
python3 scripts/check-export.py
npm run preview
```

Open http://127.0.0.1:52001/. Search is generated by Pagefind during the production build. The static output is `out/`. No API server, database, analytics, or runtime credentials are needed.

## Cloudflare deployment

The public repository’s manual **Deploy CLI docs** workflow builds the exact selected `main` commit before publishing Worker `botpager-cli-docs`. It does not publish the CLI package or deploy the BotPager API. Deployment is manual; merging alone does not publish the docs.

Before first deployment, configure the `docs-production` GitHub environment:

- Secret `CLOUDFLARE_API_TOKEN`: a scoped token permitting this docs Worker and static asset deployment in the existing Reostack Cloudflare account.
- Variable `CLOUDFLARE_ACCOUNT_ID`: the existing Reostack account ID.
- Require the owner’s approval and restrict deployment to `main`.

Credentials go in GitHub environment settings, never in this repository, build arguments, MDX, or `NEXT_PUBLIC_*` variables. The Wrangler configuration contains no account credentials. The configured custom domain is `docs.botpager.reostack.com`, selected by the owner. Deployment attaches this hostname to the static Worker in the account supplied by `CLOUDFLARE_ACCOUNT_ID`. The existing Reostack account must own the `reostack.com` zone, and the token must have the route/domain permissions needed to attach it. The owner’s visual preview approval is still required before deployment.

Local equivalent, using an already authorized environment in the intended account:

```sh
npm ci
npm run build
python3 scripts/check-export.py
npm run deploy
```

The deployment creates only static hosting. The docs contain public API origins, package names, and download URLs; these are public product configuration, not credentials.

## Content maintenance

Tutorials teach a single path. How-to guides solve tasks. Reference mirrors every CLI command. Explanation covers pairing and delivery without operational steps. Verify claims against `src/`, and use the installed-artifact E2E procedure in the CLI release docs for behavioral acceptance. The phone UI steps in the tutorial also need a real device run before claiming fresh full tutorial acceptance; existing release E2E exercises the CLI and phone API, not those taps.

## Dependency compatibility

Versions and npm lockfile are pinned independently of the CLI’s Bun lockfile. `patches/nextra-theme-docs+4.6.1.patch` makes its internal `children` validator optional: Nextra’s Layout removes children before validating the remaining theme configuration. This one-line patch allows patched Zod 4.6.7, rather than downgrading to a vulnerable schema library. `npm ci` applies it with patch-package and fails if it no longer matches. Recheck/remove the patch when upstream fixes the validator. Remaining dependency audit findings are tracked by `npm audit`; no dependency upgrades modify the CLI runtime.
